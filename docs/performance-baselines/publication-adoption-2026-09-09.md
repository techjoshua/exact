# Browser adoption of staged SSR documents

Date: 2026-09-09. Compiler correctness fix retained; staged renderer still experimental.

The browser audit uses Chromium to hydrate the marked two-child document produced by both the
current production renderer and the staged prototype, on Node and Bun. Client code is compiled
from the identical source and module identity. The test creates its root with the emitted component
receipt helper, matching the server test's prepared root. The original HTML is loaded through a
Playwright route; the client bundle executes without adding foreign DOM nodes. Each browser page
and the browser process are closed in finally blocks.

## Defect and fix

Initially, all four cases failed. The client had wrapped each independent native sibling in a
dynamic child range, while the server emitted only its component boundary. Diagnostic inspection
identified the missing dynamic range marker. Fresh native server compilation exactly matched the
stored server response, ruling out stale generated server code. Adding a root export to source
and injecting a script element were removed from the harness during investigation; neither
resolved the ownership mismatch.

The compiler previously coupled independent-sibling classification to the server target. It now
shares the ownership classification between client and server, while the ahead-of-render scheduling
helper remains server-only. Both targets omit the redundant child-range wrapper. Ordinary component
receipts still own lifecycle and parent-prop updates. The runtime's hydration checks are unchanged.

The fix belongs in native compiler lowering, not in application markup or permissive adoption.
A native compiler regression checks consistent sibling boundary ownership across targets. A
hydration package regression renders a complete document with two sibling components, adopts its
existing buttons, and verifies that a parent-owned prop update changes the first button's text
without replacing either child.

## Browser evidence

All four real-browser cases now pass: production and staged output generated by Node and Bun.
They retain the html, head, body, both strong elements, their existing text nodes, and the hydration
script. The children display their restored `Ready 1` and `Ready 2` state, do not restart their
server tasks, and each disposes once. No page errors occur. The final run uses the unmodified
browser bundle, with diagnostic rewriting disabled.

This is correctness coverage of one compiled document, not browser timing or comprehensive
hydration coverage. The staged renderer still needs native compiler integration, broader boundary,
enhancement, retry and nested-task coverage, and complete throughput comparisons. No new performance
claim against React is made.

The native compiler test suites pass and the compiler was rebuilt and stamped. Core, DOM, SSR and
hydration package artifacts were regenerated, and the Node/Bun comparison app was rebuilt. The
comparison client's asset identity remains `index-CdIXDKwS.js`; this fixture-specific compiler fix
does not change that application's current client bundle. Engineering and public hydration
documentation were updated. See the accompanying validation JSON for package-check results.

The evidence archive includes the native source/test change, package regression, compiler input
and output, browser runner, final results, server documents, and SHA-256 manifest. The overall
performance goal remains incomplete.
